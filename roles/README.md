# 自己创建角色卡

公开源码不附带可启用的角色卡、私人关系设定或聊天经历。本目录只保留这份说明；首次安装且没有角色选择状态时，程序不注入个人角色。

## 放在哪里、怎样启用

1. 在控制台“人格与角色”页面新建角色，或自己创建 UTF-8 文件 `roles/<角色名>.md`。文件名就是角色名，不含扩展名。
2. 用控制台的管理入口选择该角色。选择状态保存在本机 `state/current-role.json`；普通聊天对象没有切换角色或修改配置的权限。
3. 保存角色内容后，下一次适用的消息/唤醒会读取新内容。二代仿真会在首次投递、卡片变化、会话变化或达到重注入间隔时提供全文，其余唤醒只给引用；不会每轮重复整张卡。
4. 在控制台清除角色选择可停用角色，聊天的基础工具协议仍然保留。

新建的 `roles/*.md` 已被 `.gitignore` 排除，`roles/README.md` 例外。个人卡片保存在自己的机器上，不要随源码发布。

## 两层提示词各管什么

| 内容 | 位置 | 用途 |
| --- | --- | --- |
| 自己的角色卡 | `roles/<角色名>.md` | 身份、性格、语气、关系与自定义边界 |
| 程序的仿真协议 | `dsh/agent-presets/qq-chat{,-v2}/agent.cordis.yml` | 工具调用、读写水位、等待、分条和访问边界 |

不需要角色扮演时可以一直保持无角色状态。请勿为了“清空角色”删除仿真协议，它是程序工作所需的规则。

创建自己的卡片时，可以从以下栏目开始，内容均由自己填写：

```markdown
# 角色卡：<自定义名称>

## 身份与背景

## 说话方式

## 性格与边界

## 交流示例
```

角色卡主要描述人设，工具协议应留在仿真预设中。想要自然接话时，可以自己说明具体好奇、相关分享与自然收尾的偏好；不必给每轮强制分配问题或情绪比例。

## 按模式分段

确需区分一代和二代时，可在小节标题加 `〔一代〕` / `〔二代〕`、`[v1]` / `[v2]` 或 `（reserved）` / `（reserved2）`。程序按当前模式筛选，未标记的小节两种模式都保留，模式标记本身不会进入提示。

例如，只填写结构而不附带任何现成人设：

```markdown
## 共同要求

## 一代专用内容 〔一代〕

## 二代专用内容 〔二代〕
```

默认角色注入上限为 6000 字符，可通过 `config.json` 的 `role.maxInjectChars` 或控制台调整，允许范围 1000～20000。上限在模式筛选之后应用；控制台会提示截断风险。

角色名使用中文、字母、数字或横线，不能使用 `README`、Windows 设备保留名或路径分隔符。人格文本中不应包含 API Key、控制台令牌或其他凭据。
